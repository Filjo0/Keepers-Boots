# Hackathon requirements

Rechecked 2026-10-18 against the [official rules](https://github.com/microsoft/insidethegamehackathon/blob/main/OFFICIAL%20RULES.md). Submission requirements and deadline below remain unchanged.

- Challenge: explainable match intelligence from synthetic football data.
- Build the ingest, interpret, explain, render and personalise pipeline.
- Synthetic data creation is part of technical judging; no verified supplied tracking schema was found in public resources.
- Five equal judging areas: technical implementation, agentic design/innovation, real-world impact, user experience/presentation and category fit.
- Use Microsoft technology meaningfully; the entire advertised service catalogue is not required.
- New project, working install/demo, public GitHub repository, description and video under two minutes.
- Section 4.8 allows a website, functioning demo or test build for judging. A hosted Azure URL is not compulsory. Provide a reproducible free test route that exercises the submitted agent workflow, including model setup; an agents-off run alone demonstrates only the deterministic experience. Access must remain available through the judging period, which ends 10 November at 23:59 Pacific.
- Best Multi-Agent System explicitly recognises Microsoft Agent Framework, distinct agent roles, shared state, handoffs and recovery. Autonomous tool selection is not listed as a requirement. The category asks for a result a single agent could not achieve as effectively; that benefit still needs evidence here. Foundry and Azure-specific categories require their respective technology.
- Teams can have up to four members. Eligibility and rights must be checked against the full rules.
- Registration closes 20 October 2026 at noon Pacific.
- Submission closes 27 October 2026 at 23:59 Pacific.
- Perth equivalents: 21 October 03:00 and 28 October 14:59, respectively.
- Registration completed by the user, reported 2026-10-10. Submission, public publishing and cloud provisioning have not been performed.

## Fit and remaining uncertainty

The implementation maps the five stages to a synthetic scenario/frozen-state input, computed timing evidence, interpreted explanations, browser rendering and different fan/analyst views. It is an on-demand replay prototype: streaming event ingestion and responsive live-match narration are not verified. The brief asks for events as they happen and football-realistic synthetic data; those are fit risks, not covered by passing software tests. Scenario realism and multi-agent benefit need separate evidence.

Section 4.8 permits a test build but does not explicitly approve recorded AI fixtures as the sole test of an agent entry. Recorded mode is a labelled captured-run demonstration; retain functioning live code/setup and describe both modes accurately. Organizer acceptance remains unconfirmed. Submission still needs public code, an English description/video, free judging access, entrant eligibility and rights clearance. A root open-source LICENSE is our release choice, not an explicitly named submission-file requirement.
